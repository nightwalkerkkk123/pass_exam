# 网络三件套首次复习 — 连环追问模式

2026-08-05 首次网络面试复习会话。采用连环追问模式（用户选择），覆盖 HTTP/1.1→2→3 演进、HTTPS+TLS 握手、TCP 四次挥手与 2MSL 三个主题。综合验证环节串联 RTT 计数。

## 已确认掌握（选择题验证）
- **HTTP 演进因果链**：1.1 应用层 HOL → 2 多路复用（治好应用层 HOL、引入 TCP 层 HOL）→ 3 QUIC 流独立。四连对。
- **HTTPS 混合加密分工**：非对称商量密钥、对称传数据。
- **TLS 1.3 砍到 1 RTT 的根因**：删 RSA 只留 (EC)DHE → 算法空间变小 → 客户端能预判 → 密钥素材提前塞进 ClientHello。安全精简与握手提速是同一件事。
- **TCP 四次挥手根因**：全双工，ACK 与自己的 FIN 不能合并。

## 纠正的误解（高价值）
1. **2MSL ≠ 经验值**：初答"经验调参值"。纠正后理解 2 MSL = ACK 最长存活 1 MSL + 重发 FIN 最长传输 1 MSL，是数学最坏上界。MSL 的数值（30s）才是工程经验。
2. **反向提问陷阱**：在"哪条错误"题中误选了正确的描述。知识本身没问题，是审题问题。对策：先圈题干关键词再读选项。
3. **TLS 1.2 为什么 2 RTT**：追问后掌握——客户端的密钥交换消息依赖服务器先发来的证书/DH 参数，必须一来一回。

## 薄弱点（下一步教学方向）
- **RTT 计数**：首次答"2 个"（正确 4 个），漏算 TCP 握手和 HTTP 往返。需练变形题（含 keep-alive 复用、0-RTT）。
- **开口复述**：倾向"我懂了下一个"，综合验证需强制开口。

## Implications
下一步可推进：① TCP 三次握手深挖（为什么不是两次）；② TLS 证书链验证细节；③ HTTP/3 连接迁移机制；④ RTT 计数变形题专项。
